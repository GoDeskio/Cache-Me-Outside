# Roadmap

These are proposals. None of them are implemented in the foundation branch. They are the next changes that look worth doing on top of Valkey for this home-lab cache, in an order that keeps each one reviewable on its own.

## Proposals

1. **TLS on the listener.** Terminate TLS in `valkey-server` (`BUILD_TLS=yes` is already a Valkey build flag) with a certificate and key mounted from a Docker secret or an untracked file. Clients would verify the certificate. The current deployment is plaintext on a private address.

2. **Off-volume backups.** A scheduled job, separate from the cache process, that copies `dump.rdb` and the AOF manifest from `cache-me-outside-data` to another disk. Restores would be a documented `valkey-check-rdb` / `valkey-check-aof` pass before the files are put back.

3. **One ACL user per app.** Replace the single shared app user with a directory of secret files, one user each, generated by the entrypoint. A compromised app password would not be the password for every client.

4. **Metrics without giving apps `INFO`.** `INFO` is in `@dangerous`, so the app user cannot scrape it. A proposal is a sidecar or a local admin-only scrape that exports a small set of Valkey metrics (memory, evictions, AOF delay, rejected connections) for the home-lab dashboard.

5. **ACL denial visibility.** Turn on periodic reading of `ACL LOG` with the admin user and ship denials to the host log, so a client using `KEYS` or `FLUSHALL` shows up without enabling those commands.

6. **Measured runtime tuning.** Before changing `io-threads`, active defrag, or the jemalloc background thread, run `deploy/bench.sh` against the current defaults and record the results file. Only keep a change that shows up there on this hardware.

7. **A replica profile.** A second Compose profile with one replica, both ports still bound to localhost or a single LAN address, for failover practice. Not cluster mode. Cluster mode is a later step if one node's memory is no longer enough, and it would use the same host-bind check.

8. **Changelog next to sync pull requests.** When the weekly upstream sync opens, add a short note of Valkey fixes we care about (persistence, ACL, protocol) so the review is not only a raw merge.
